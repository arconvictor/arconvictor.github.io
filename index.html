DBA Password Rotation Tool DBA-Passwort-Rotationstool Herramienta de Rotación de Contraseñas para DBA

A Java command-line tool for database administrators to securely rotate passwords for technical database users — the service accounts applications use to connect to a database. Supports bulk operations from a text file or direct CLI input, and keeps the database and HashiCorp Vault in sync per user. Ein Java-Kommandozeilentool für Datenbankadministratoren zur sicheren Rotation von Passwörtern technischer Datenbankbenutzer — der Service-Accounts, mit denen sich Anwendungen mit einer Datenbank verbinden. Unterstützt Massenoperationen aus einer Textdatei oder direkte CLI-Eingabe und hält Datenbank und HashiCorp Vault pro Benutzer synchron. Una herramienta de línea de comandos en Java para que los administradores de bases de datos roten de forma segura las contraseñas de usuarios técnicos — las cuentas de servicio que usan las aplicaciones para conectarse a una base de datos. Soporta operaciones masivas desde un archivo de texto o entrada directa por CLI, y mantiene sincronizados la base de datos y HashiCorp Vault por cada usuario.

Spured — Auditable Data Versioning Spured — Nachvollziehbare Datenversionierung Spured — Versionado de Datos Auditable

A Java / Quarkus service built for an insurance company to comply with regulations that prohibit deleting customer records. Instead of deletion, it versions and hides outdated data from day-to-day operators, while preserving a fully auditable history — who changed what, and when — accessible only to auditors and DBAs. Ein Java-/Quarkus-Service für ein Versicherungsunternehmen zur Einhaltung von Vorschriften, die das Löschen von Kundendaten untersagen. Statt zu löschen, versioniert der Service veraltete Daten und blendet sie für den operativen Betrieb aus — bei vollständig nachvollziehbarer Historie, wer was wann geändert hat, einsehbar nur für Auditoren und Datenbankadministratoren. Un servicio en Java/Quarkus construido para una aseguradora, para cumplir con regulaciones que prohíben eliminar registros de clientes. En vez de borrar, versiona y oculta los datos desactualizados de los operadores del día a día, preservando un historial completamente auditable — quién cambió qué y cuándo — accesible solo para auditores y DBAs.

Two-Node Homelab Infrastructure Zwei-Knoten-Homelab-Infrastruktur Infraestructura de Homelab de Dos Nodos

A self-hosted homelab I designed across two Proxmox VE nodes, built up piece by piece rather than all at once — the environment where I practice systems administration and DevOps work that doesn't show up in a typical junior dev's day-to-day, running ~30 LXC containers and VMs today. Highlights so far: a highly-available reverse proxy (Keepalived/VRRP, automatic failover), a firewall segmented per service with explicit default-deny rules, infrastructure automation with Ansible (dynamic inventory — still deepening my hands-on experience here), and an observability stack (Grafana, Loki, Prometheus) monitoring 40+ internal services. Ein von mir entworfenes Homelab auf zwei Proxmox-VE-Knoten, Stück für Stück aufgebaut statt auf einen Schlag — die Umgebung, in der ich Systemadministration und DevOps-Arbeit übe, die im typischen Junior-Entwickleralltag nicht vorkommt, aktuell mit ~30 LXC-Containern und VMs. Bisherige Highlights: ein hochverfügbarer Reverse Proxy (Keepalived/VRRP, automatisches Failover), eine pro Dienst segmentierte Firewall mit expliziten Default-Deny-Regeln, Infrastrukturautomatisierung mit Ansible (dynamisches Inventar — hier vertiefe ich meine praktische Erfahrung noch), sowie ein Observability-Stack (Grafana, Loki, Prometheus), der über 40 interne Dienste überwacht. Un homelab diseñado por mí en dos nodos Proxmox VE, construido de a poco en vez de todo de una vez — el entorno donde practico administración de sistemas y trabajo de DevOps que no aparece en el día a día típico de un desarrollador junior, hoy con ~30 contenedores LXC y VMs. Puntos destacados hasta ahora: un proxy reverso de alta disponibilidad (Keepalived/VRRP, failover automático), un firewall segmentado por servicio con reglas explícitas de denegación por defecto, automatización de infraestructura con Ansible (inventario dinámico — todavía profundizando mi experiencia práctica acá), y un stack de observabilidad (Grafana, Loki, Prometheus) que monitorea más de 40 servicios internos.
